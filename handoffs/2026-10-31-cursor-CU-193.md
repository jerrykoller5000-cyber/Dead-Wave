## How an agent without Playwright gets a browser check
Ask Cursor: `node crew/crew.mjs request <you> cursor "run <the check>" "<the command>"`. Cursor runs it on this PC through the slot.
Or write the check on `tools/cdp.mjs` (Chrome or Edge is already installed; `launch`, `newPage`, `goto`, `evaluate`, `screenshot`). The slot still wraps it, because `launch` refuses without a lease. Playwright is not a dependency of this repo (`tools/cdp.mjs` says why, at the top). Do not `npm install` it.

## The fixture
`canTrack` (ui/objectives.js, committed) keeps a site only when it is reachable or navigable. The fixture's `fresh()` marks every site `reachable: false`, then `scenario()` sets reachable on one site, and it calls `app.track(id)` on the line before that. `track` therefore returns false, and only the radio site (set reachable by the opening `scenario()`) is a marker.

So the CDP run, which follows ui/objectives.browser.mjs, got:
- 1 marker, not 7
- clicking `[data-site="objective:medical-convoy"]` finds nothing
- `scenario('active' | 'interrupted' | 'full' | 'partial')` does not take (the card keeps the radio track from the Enter), so the progress, status and remaining lines fail
- the READY move puts the card in `#briefing-report` (count 1) but it stays hidden, because that `scenario('available')` also tracks before the site is reachable
- no page errors

Enter on a focused button had to be a click: a CDP key event does not activate a button the way Playwright's keyboard does. After that, "Restore the radio mast" passed. The 7-marker miss and the track-before-reachable misses are the page as it stands. ui/ is ChatGPT's; I did not edit it.
