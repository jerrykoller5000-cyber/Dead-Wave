## Night-fight candidates, worst first

1. **Objective markers and tracker.** GP-19969 / CL-263, `ui/objectives-runtime.js:36`, `ui/objectives-runtime.js:45`, `ui/objectives-runtime.js:76`, `ui/objectives-runtime.js:86`, `ui/objectives-runtime.js:114`; `ui/objectives.js:13`, `ui/objectives.js:121`, `ui/objectives.js:132`. The existing independent `requestAnimationFrame` poll calls `update()` every 100 ms during play, including night 20. 1.1 passes the story snapshot and admits a story-open site as navigable even when the player is nowhere near it. Whenever an open marker is active and the player moves, the signature includes raw player coordinates, so the view can repaint at 10 Hz. `paint()` then writes each visible marker's `title`, `aria-label`, `aria-pressed`, `style.left` and `style.top` without a value check, and touches the tracker card's labels/visibility. The 1.0 loop and DOM writes already existed; the extra work is the distant story-open markers and story checks. Cheap fix: cache each marker's label, pressed state and projected position and write only values that changed; quantize or compare displayed distance before repainting the tracker. Keep the 100 ms input/model check. This is the strongest source candidate for sustained browser work, but its effect depends on an open lead and needs AG-162's trace.

2. **First-person world prompt.** CL-260, `index.html:31010`, `index.html:31031`, `index.html:31108`. When an interaction prompt is showing, `updateKioskPrompt()` calls `placePrompt()` on each render frame, even between the 100 ms text refreshes. 1.1 adds the under-crosshair position for an over-head or off-screen anchor in first person. The function still projects a 3D point, checks the `offscreen` class and compares a `style.transform` string every frame; it writes transform only when the string changes. In the centered first-person case the coordinates normally stay fixed, so this is repeated JS/DOM reading more than repeated layout. Cheap fix: for known centered prompts, use a cached viewport-center transform without projecting the world point; update the class and transform only when camera mode, prompt anchor or viewport size changes. Check the ordinary moving world prompt separately so it still follows its target.

3. **First-person pickup duplicate.** CL-260, `index.html:31049`–`31072`, called at `index.html:31093`. `updateFpNote()` runs each render frame during night 20; once the notice exists, it reads `style.opacity` every frame and writes it only on show/hide edges. A `MutationObserver` on `#supplyNotice` copies changed `textContent` to the new note when a pickup appears. This is per-pickup DOM text and a 0.2 s opacity transition, not a continuous text rewrite. Cheap fix: cache the visible boolean and use the observer plus an expiry timer to change opacity, leaving the frame loop out of a state that changes only on pickup, pause and view changes. Priority is below the marker path because the steady-state write is guarded.
