## What GP-19952 found, and why frame 780

`marineShadowBuilds` counted one build per page, but the profiler's build is three's node build, which happens the first
time the proxy is *drawn*, not when it is built. On the bench path he lands, the night is jumped to at once, and the proxy
is built a second later, after the night's one shadow redraw (CL-237). In the night proper the map is next drawn 900
frames later, unless he moves 16 m, and that frame paid for the proxy's shader. ~120 frames before the profiler starts +
~780 into it = 900. In real play the same first draw came a second after landing, in the day: one 25-35 ms frame.

Measured in the cloud, the device's index.html as it stands (before) and with CL-241 (after), WebGL in software,
Medium, a 480x270 window (`qa`-style probe, not committed: one page, logs `TT.marineShadowDbg()` and three's
node-builder cache):

| | before | after |
| --- | --- | --- |
| built at load | no | yes, frame 10, 8-11 ms, 96 bones, drawn at frame 10 |
| after landing | built (68 bones; one new node build) | nothing |
| a part shown, by day | built at 69 bones: one new node build | built at 96 bones: no new node build |
| a part shown, in the night proper | built; not drawn until the next timed redraw | built, the map redrawn once, drawn the next frame, no new node build |

The landing rebuild was the rig skin (CL-210): it is baked again at every match start, and its eight new skinned
meshes changed the proxy's signature though the proxy never takes skinned meshes. The signature now leaves them out.

## How

- `warmMarineShadow()` runs in `maybePreRollFromLoop` just before the staged fight shows the hidden parts for its
  compile, so the proxy is his real set of parts and the fight's shadow compile and frames build its pipeline.
- `buildMarineShadowProxy()`: the old proxy leaves the tree at once but is disposed by `flushMarineShadowRetired()` only
  once the new one has been drawn (`onBeforeRender` marks it), or after 3600 frames. three drops a node build when its
  last render object is disposed; disposing first (as `skinUnmerge` does) meant every rebuild built it again.
- The skeleton is padded to 96 bones (128 above that) by repeating the last bone, as CL-227 does for the zombies:
  three puts the bone count in the shader and its cache key.
- In the night proper (the shadow map not drawn every frame) a rebuild calls `sunShadowRedraw()`.
- `?shadowproxy=0` still turns the proxy off; shadows off (Low) still unmerges it, and the retired ones go at once.
