# cursor — CU-57 the 1.0 package as a desktop app — 2026-10-06
Changed: Dead-Wave now builds as a Windows desktop game: an installer (226 MB, per-user, no admin) that puts `dead-wave.exe` (3 MB) and the game's files in one folder, with the PGB patch as its icon. The window opens fullscreen (F11 toggles), has no browser chrome, runs the game on WebGPU, shows the version on the title, keeps the profile in a visible file (`Documents\Dead-Wave\profile.json`), and Quit ends the program. The browser build is unchanged (`Play Dead-Wave.bat`).
How: a Tauri 2 shell (Rust, using the WebView2 that comes with Windows) in `desktop/`. A custom protocol (`dw:` = `http://dw.localhost/`) serves the installed `game/` folder, with byte ranges for the intro video; an init script seeds localStorage from the profile file before the game's own code runs and writes every later change back. `tools/package.mjs` stages exactly what the game loads (index.html and assets/ core/ game/ studio/ ui/ vendor/ world/, no tests, no WAV originals, 244 MB, 271 files) into dist/dead-wave and checks the copy by booting it.
Files: desktop/ (package.json, README.md, make-icon.mjs, smoke.mjs, src-tauri/: Cargo.toml, build.rs, tauri.conf.json, capabilities/, boot/, icons/, src/main.rs), tools/package.mjs, tools/cdp.mjs (attach(): a browser that is already running), core/version.js, index.html (the version in the title's footer, its CSS, the import and one call), .gitignore (dist/, desktop/node_modules/, desktop/src-tauri/target/).
Tests: node tools/package.mjs → the staged copy boots in headless Chrome: title and a match, 153 files fetched, none missing, no page errors, "v0.1.0" on the title. node desktop/smoke.mjs (the built exe, this PC's WebView2 and GPU) → 13 pass, 0 fail: the title comes up from the protocol; the shell's script ran first; the renderer is WebGPU; the version is on the title; the window is fullscreen (1920x1080); a match starts and the insertion plays out (video and sounds through the protocol); no file the game asked for was missing; a localStorage key is in profile.json; no page errors; after a restart with the webview's own data wiped the keys come back from the file; a removal is written too; window.close() (the menu's Quit) ends the program. The same 13 on the INSTALLED copy: silent install to a scratch folder (17 s), smoke, silent uninstall (the folder is gone, no Documents\Dead-Wave left behind). npm test -- t0 t29 t144 t102 → 4 checks green (the title and wardrobe with the new footer); the browser build also shows "v0.1.0".
