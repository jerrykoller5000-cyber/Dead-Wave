## Implementation and reproduction

The new geometry remains opaque and double-sided through the existing vertex-colour foliage merge. Root shading and tip colour are baked once into the plant geometry, then carried through the existing chunk merger. Wind/trampling weights still derive from vertex height, and build clearing still collapses the complete recorded vertex span beneath the terrain. The browser check exercises that exact clearing path.

The geometry factory uses the vendored Three build through dependency injection, with no network or new dependency. Unit checks cover finite normals/coordinates on drawn vertices, deterministic geometry, bounded triangle counts, rooted/tapered grass, fern spread and non-destructive colour shading. SphereGeometry’s unused pole vertices are not treated as drawn faces.

Browser runner needs the already installed Playwright runtime:

    $env:NODE_PATH='C:/Users/Zero/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules'
    node world/ground-foliage.browser.mjs --before --baseline --bench
    node world/ground-foliage.browser.mjs --bench
    node world/ground-foliage.browser.mjs --night

`--baseline` reconstructs only the old foliage shapes/colours in the served page in memory against the current world. It does not revert or write index.html. Its698,190-vertex count matches the original before-edit capture. The actual working page is served unchanged for the after run apart from test-only debug exposure. Stats and benchmark JSON are beside the shots.
