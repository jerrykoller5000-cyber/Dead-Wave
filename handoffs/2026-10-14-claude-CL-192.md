## What changed

1. **The menu opens on its pan (Jerry's #2).** CL-191's gate moved the warm-up after the intro videos, but the menu
   still opened on the first tick, so it showed the camera parked on the HQ while the staged fights ran (and their
   sounds) before the menu camera started. Now index.html runs set A, the staged fight and the live fight behind the
   opening, then 8 ticks of the menu camera, then `releaseTitle()` → `DWOpening.ready()`. While the opening still
   covers the screen after that, the tick draws nothing (`if (_titleReleased && DWOpening.active) return`), and the
   game's sound stays at zero until the opening is gone. Seen on his machine: the menu revealed on its pan, 59 fps.
2. **Two gates** (opening.js): `gpuGate('compile')` opens when the caracal ends (post-processing set-up, effect pools,
   the async compile, under the title card); `gpuGate('warm')` opens with the loading screen (the synchronous warm
   frames and fights; the screen is static, so a held frame shows nothing). Either opens for a hidden window and
   after 60 s. `?gpugate=late|caracal|now|all` moves them for measuring; default `late`.
3. **The title card.** The gate's waiters run 120 ms after the phase change, so the title paints before the game takes
   the main thread (the 2.7 s block used to land in the same task as the phase change). The signal line's draw-on is now
   a compositor animation (`signalGrow`: scaleX + opacity) instead of `stroke-dashoffset`, which needs the main thread.
   Not yet seen on his machine.
4. **The shader compile now compiles what the game draws** (`compileForLiveTarget`, index.html). compileAsync was
   aimed at the canvas, but with post-processing on every frame draws the scene into the scene pass's render target
   (4× MSAA, half-float, tone mapping off), and a GPU pipeline is keyed on the target, so those pipelines were never
   used and the first warm frame built them all again synchronously. It now sets the render target, tone mapping and
   colour space the way PassNode/PostProcessing do and restores them before returning. Headless WebGPU: the compile
   still makes 97–99 async pipelines; the first warm frame went from **85 synchronous pipeline builds to 8**. The low
   preset (no post chain) and `?post=off` keep the old call.
5. **The live fight ends when it has nothing left to compile.** It ran a fixed 110 ticks (~2.3 s); now it ends once no
   new shader variant or pipeline has appeared for 12 ticks, from tick 60 and after the pooled bodies are built,
   capped at 110 (and the full 110 if the renderer internals it reads move). Headless WebGL: the last new variant
   came at tick 65, the fight ended at **tick 77**, and the variant count was the same as with 110 ticks. About 0.7 s
   less loading screen at Jerry's frame rate. Mark `warm-live-end` records the tick.
6. **A recorder on every launch** (assets/intro/opening-perf.js, `window.DWPerf`): segments, frames over 33/50/100 ms
   and the worst one, gaps over 50 ms, both videos' decoded/dropped frames per segment and each drop with its time and
   the last mark before it, long animation frames with the script that held them, the game's load steps, and marks from
   the game (gates, post, pools, compile, warm-up stages, menu camera, renderer + preset). It finishes 6 s after the
   menu, posts to the dev server and logs one summary line. tools/serve.py takes the POST at `/__perflog` and writes
   `qa/perf/opening-<time>.json`. The packaged game has nothing listening; the recorder just ends.
7. **The disclaimer: B2 "Tell 'em!"** in the line-3 pause (it was B1's "You heard?" twice), subtitled
   "( tell em! )". tools/disclaimer/timeline.json chirps are now objects `{at, file, lead, text}`; mix.py chains each
   file through the far-voice treatment; scene.js shows each chirp's own text. disclaimer.mp4 re-encoded from the same
   frames: only the audio from 12.14 to 14.24 s and the subtitle in frames 726–787 changed.
