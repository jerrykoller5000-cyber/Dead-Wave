# GB-128 - New key layout (Jerry, final say)

Agent: Grokbot. Date: 2026-10-02 (CT).

## Changed
- Global keydown handler in index.html:
  - Digit1 = night vision (was N), Digit2 = flashlight (was L), Digit3 = laser (was Z), Digit4 = holster/draw (was U).
  - X = fire selector SEMI/AUTO (was K), but only outside build mode.
- X sells/scraps ONLY in build mode (placeMode || buildMode). The build-mode behaviour is unchanged: hold X to
  preview, release to scrap the piece under the reticle, hold + drag for a box; when carrying the mortar it
  falls back to sellNearestBuild as before. Outside build mode X never sells.
- N, L, Z, K and U are unbound (free).
- One toggle per press: Digit1-4 and X ignore e.repeat, so a held key doesn't flicker.
- Digits 1-9 with B held still turn the build-wheel pages. That gate (wheelKind === 'build') sits earlier in the
  handler and returns, so 1-4 do their job only when B is not held.
- New typingInField(el): a focused text field, textarea, select or contenteditable keeps 1-4 and X off.
  Checkboxes and sliders don't count, so a settings toggle left focused doesn't eat the keys.
- Digit4 (holster) and X (fire mode) only act in a live match (gameStarted && !gameOver && !won).
  U and K used to fire on the title screen too. Digits 1-3 keep the gear functions' own guards.
- Other contexts are unchanged because their early returns all sit above the new lines: dev console, name
  field, scripted kill/grabs, burial, shop, CIF (dressing room/armory), pause/settings, wave briefing (captures
  keys itself), objectives/prep checklist guards. Mortar, ladder and swimming don't use these keys. The toggle
  functions keep their own guards (needGear, swimming, etc.).
