## Which side is "left"
The character's own left. Soldiers and zombies both face +z (marine nose at +z, aimYaw = atan2(dx,dz); zombie hands at +z), so their left is +x: the arm the code calls armRG / "right" and that holds the gun. The marinesheet front view shows the old light placeholder on that arm on the viewer's right, which is his left. If Jerry meant the non-gun arm, it is a one-token flip (side>0 -> side<0 in marine-body.js, armRG -> armLG and the sign of x in the zombie block).

## How
- Asset: cropped the shield from Jerry's 1280x720 image by a shield-silhouette mask, background to alpha, resized to 192x224 (not 256 wide: t123 counts any 256-wide map as camo), quantised to 256 colours. 14 KB, under the 30-40 KB guide with no visible loss.
- Texture: a 192x224 canvas, CanvasTexture, colorSpace sRGB (house rule for colour art, as the camo and mural maps), MeshStandardMaterial roughness 0.95, alphaTest 0.5 (cut-out, not blended: no sorting, no transparent variant). The PNG is drawn into the canvas on load and needsUpdate is set; until it arrives the canvas is clear and nothing shows. The path is relative; if that 404s (tools/tests/test.html is not at the root) it retries from /assets/.
- Material, texture and the PlaneGeometry(1,1) are userData.shared and are never tinted or disposed: the zombie hit flash, night rim and charring use bodyMats only (the merged per-zombie mats); the wardrobe touches only its item materials; dressInMarpat swaps only camoTex maps.
- makePgbPatch is an arrow, not a function statement: tools/check-players.mjs reads the code after a function statement as inside it, and blamed the players-list code below on it.
- Soldiers: in marine-body.js the left arm's flat 7 mm box is replaced by a 0.062 x 0.072 m plane at x .096 (1 mm off the raised block, whose face is at .095), turned +PI/2 about y so it faces out and reads the right way round. The right arm keeps its patchInk box. The plane is kept out of mergeRigidMeshes (which would box-project its UVs). Draw calls: unchanged for soldiers (the left box was the only patchMat mesh in its arm group, so it was already its own draw; the plane replaces it one for one).
- Legacy body (makeMarine({legacyBody:true}), GP-106 review only) is not patched.
- Zombies: a 0.075s x 0.087s plane at (0.067s, -0.09s, 0) on armRG (upper arm face at 0.065s), turned +PI/2. pgbPatchMat is in compactZombieMesh's keep set so it is not merged into vertex colours (the upper arm is then the group's only other mesh, so nothing else changes). +1 draw per military zombie.
- Limb loss: detachZombiePart hides the arm group, so the patch goes with it; the flying piece is a clone sharing the material; gib cleanup disposes only its own top-level mesh. Pooling: resetZombieMesh strips only userData.stump meshes and re-shows every child, so the patch survives. disposeZombieMesh (no callers today) would dispose every material including the shared one; left alone, worth a skip-shared line if it is ever wired up.
