## Wiring later

- `mountObjectives({mapRoot,hudRoot,project,onTrack})` explicitly mounts the component; nothing auto-mounts. Import its CSS separately. The caller owns container placement, map rotation/projection and gameplay visibility.
- `update({runId,sequence,active,player:{x,z},sites})` accepts a newer full snapshot only. Call `reset(newRunId)` for a new run or restore; old-run packets cannot repopulate cleared state.
- Each site supplies `id`, `state`, `position:{x,z}`, `reachable`, optional progress 0..1, optional feedback `full|partial|interrupted`, and optional `reward`/`remaining` as `{key,params}` for the text catalogue.
- States: `undiscovered`, `available`, `active`, `ready-to-claim`, `claimed`, `unavailable`. Only the three open states appear on the map. Completion/removal clears the selected tracker and announces its outcome. Full/partial inventory keeps the objective open.
- Map projection returns normalized `{x,y}`. Off-map/invalid positions are omitted, not pinned to misleading locations. One selected marker at a time; keyboard focus survives snapshots.
- Reachability and progress must come from the objective owner. UI never infers usable distance, awards supplies, handles E, charges Cash, starts timers, mutates the world or writes saves. It displays the existing keyed E action only when the supplied snapshot permits it.
- Fixture quantities are presentation examples, not final rewards. Production must use GP-8 reward definitions and the live supply catalogue, preserve partial quantities, and send a confirmed terminal state only after the authoritative claim.
- Controller tests include old snapshots, reset, caller mutation, duplicate sites, bad positions and unknown copy. Browser check covers selection/untracking, focus, pause hiding and a 390px viewport.
