# CL-232: the zombie bodies' glow, one node graph; bench --prof journals node builds

**What AG-108 showed (CL-229 in):** night 20 High 53.4 / 57.3 / 56.8 fps, 1 % low 28.2 / 34.8 / 26.2. Pipeline spikes:
0 (CL-229 worked: zombie skins share one program). But 25-29 frames over 25 ms a run remained, nearly all with
23-40 ms in `r:render` and ~10 MB of heap, the signature of a build, just no new pipeline. three r175 keys a material's
compiled node state on its node graph's node ids (`getCacheKey$1` pushes `node.id`), so a material with a node graph
of its own builds it again (the node builder, the shader text, the bindings) the first frame it's drawn, even when the
text comes out the same as another's and the pipeline is shared.

**The zombie bodies:** every glowing zombie skin (eyes, the demon's embers: GP-19939) built its own emissive graph
(`materialEmissive + zGlow.rgb * mix(reference(ud.eyeMats.0...), reference(ud.emberMat...), zGlow.a)`), so each new
zombie body was a build.

**Changed (index.html):** `zombieGlowNode()` builds that graph once; it reads `userData.zEyeGlow` and
`userData.zFireGlow` of the body being drawn (a reference node with no object refers to the object it's drawing).
Each skin gets those two as getters over its zombie's eye and ember materials (not enumerable, so cloneLean never
copies them). Same pixels, one build for every body of a kind. Verified in a three-only probe
(`qa/2026-10-21-CL-232/glow-probe.html`, headless WebGPU): four skinned bodies with their own materials and their
own eye and ember levels: 4 node builds before, 1 after, and the glows read back the same, also after changing one
body's level.

**bench --prof:** a journal of node builds (`renderer.backend.createNodeBuilder`, called only on a cache miss):
`prof.builds` (made, the top groups by object | kind (x count for an InstancedMesh) | material, with frames), each
spike's `newBuilds`, and `builds` in spikeCauses (between pipelines and uploads).

Tests: t270 5/5 on the real renderer (cloud, --soft): skeletons 32, and one shared glow graph, every body reading its
own levels; t93 11/11 on the test page. Not verified: night 20 on the 5080 (AG-109).
Known next: InstancedMeshes with more than one instance key their build on the object's uuid in r175
(`getMaterialCacheKey`), so a demon's fire fists (x2) and a screamer's vapour (x36) build once per new demon or
screamer body; the journal will say how often.
