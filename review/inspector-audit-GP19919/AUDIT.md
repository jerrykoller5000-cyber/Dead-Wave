# Marine Inspector audit — GP-19919

Jerry's request: make `Open Marine Inspector.bat` a dependable shared tool for model and animation review, with a workflow that both people and agents can use. Audited on 2026-10-14 against the live checkout; no commits, pushes, asset replacements or ordinary-game balancing changes were made.

## Result

The same BAT opens the live-game inspector, now version 1.1.0. It reviews the actual game builders and sends marine moves through the game's own input/pose code. Claude's CL-196 foundation remains authoritative; Antigravity's earlier copied inspector is retained as a reference. There is one maintained implementation of the models and motion.

The inspector has a safer launcher, cancellable and isolated review operations, working move readbacks, actual-pose camera framing, saved review setups, reliable resource cleanup, and a versioned agent API. The camera CLI and file inbox can capture those setups and return explicit failures. The full operating and extension guide is [studio/inspector/README.md](../../studio/inspector/README.md); shell/inbox examples are in [tools/CAMERA.md](../../tools/CAMERA.md).

## Findings and repairs

- **Launcher could kill an unrelated application.** The BAT killed whatever owned port 8975 and guessed readiness after a delay. It now verifies checkout identity and loaded server-code fingerprint, reuses a matching server, and chooses a free port otherwise. Launches are serialized, background processes are hidden, and failures name the server log. Node 22 is checked. Stale listeners are preserved rather than mistaken for the current tool.
- **HTTP startup could stall before the game module loaded.** Buffered full-video responses ignored byte ranges and occupied the browser's local HTTP connections. Bounded streaming, correct single-range responses and disconnect cleanup restored four-page startup. The identical retained pages reached TT in 15.7–16.4 seconds, versus staying at Connecting / 0% after 45 seconds before the repair.
- **Malformed notes could crash the server; failed saves could lose the draft.** Null/non-object JSON, oversized input, origin checks and disk errors now return controlled responses. Saved pictures have distinct names. Notes share a stage/capture transaction, include a recipe, await success or clipboard fallback, and preserve unsaved text on failure. A native review note and picture were saved and the proof note was answered on the crew board.
- **Stopping a move did not stop its future input.** Delayed grenade, fire, dive and mount sequences could continue in the next review. Moves now carry an AbortSignal; Stop releases canonical inputs and phase holds before the next setup. Charged grenades are cancelled through the game's existing blur path. Failed kit setup does not silently continue the move.
- **Move and loop controls reported frozen values.** Accessors copied with Object.assign became initial values, so the selected move was always null and looping appeared always on. Live getters, accurate readbacks, visible asynchronous state and scoped UI refresh callbacks now reflect the actual desk.
- **M240 carry, mortar and knockout contaminated later inspections.** The old clear path called an unavailable set-down export, swallowed the error, and left carried weapons and placement ghosts. The desk now uses the canonical set-down hook, owns newly created replacements, removes only its own props, verifies mount/carry success and restores knockout transforms, wake, blackout and audio state.
- **A new inspection could inherit a prone/airborne dive.** The inspector-only placePlayer hook now resets the existing dive/jump state and grounding. This does not change the ordinary-game dive path.
- **Camera bookmarks assumed an upright body.** Full/three-quarter and Frame fit the actual posed bounds. Head, torso, hands, back and boots follow their live world joints. Bounds refresh is cached rather than traversing every mesh every frame; camera distance does not pump with each breath. Drive releases the inspector camera correctly.
- **Batch jobs could overwrite each other's stage.** Check, sheet, restore, capture and note transactions are exclusive and cancellable; getters remain available. Invalid IDs, modes, variants and numeric inputs fail clearly. Empty filters are errors. Frame waits, GPU waits and image allocations are bounded; failed render operations release the hold.
- **Checks did not cover every variant.** The default check now covers all 182 current catalog cases, including build tiers, fish and cave variants. Zombie geometry checks use statues; live/walk/rise and reactions are separate reviews. Runtime errors make a case fail rather than quietly producing a green tile.
- **Rewind erased history on reparenting and overstated what it restored.** Stable rig-node indices preserve history when a gun is reparented; parent edges restore safely. The ring honors its memory budget. It restores transforms, hierarchy and visibility, not ammunition, AI, arbitrary geometry buffers or material state. Play returns to the newest pose before simulation resumes.
- **Model switching risked leaking or disposing shared GPU resources.** Resource scopes protect scene and detached game roots, shared materials/maps and weapon context, then dispose owned allocations. Stale asynchronous builders cannot attach after a newer selection. Intentionally opaque shared caches must be marked `userData.shared = true`.
- **Geometry diagnostics could be wrong.** Bounds include per-instance matrices and changed vertex buffers, exclude hidden/non-finite objects and main-camera-excluded layers, and place axes in world space. Lines and points no longer inflate triangle counts. The suite's missing TSL namespace and empty InstancedMesh bounding-box stub now match the pinned runtime; no assertions were weakened.
- **Marine measurement caused CPU spikes.** The visible shadow-only merged SkinnedMesh is excluded from the main camera, but the old measurement CPU-skinned all its vertices and double-counted its triangles. Actual native profiling found bounds work averaging 22–24 ms and Marine rendering near 52 FPS. Camera-layer-aware bounds retain the real posed body and cloth while skipping the shadow proxy; the paired final performance proof is in `runtime/`.
- **Automated pictures could reset the animation being reviewed.** Same-subject shots preserve the move and kit; `--reset` rebuilds explicitly. Screenshot sidecars include the whole review recipe, and `--from` restores it before applying the exact camera. Old sidecars remain accepted. Legacy weapon suppressor targets retain their attachment.
- **GPU pixels could describe the previous subject while the UI described the new one.** Visual inspection of the inbox proof exposed a stale M4 image under the Marine panel. Explicit inspector draws now refresh the renderer's frame-cached scene pass; the external capture hold draws again, waits for the public GPU completion fence and copies the source into a temporary bounded 2D canvas beneath the panels. Resume/cancel/failure remove the copy. Viewport changes invoke the game's resize handler and verify actual canvas dimensions. Inspector chrome remains attached to its compositor tree. The renderer-specific frame adapter stays inside inspectHost, guarded for the test/WebGL renderer.
- **Tool processes stayed alive after successful completion.** Successful CDP RPC replies retained their deadlines, including an hour-long batch timer. Reply, socket-close and synchronous-send paths now clear their timers and reject pending work. Controlled native audit scripts exit and close only their own browser/server.
- **Controls were fragile on small windows or bad saved settings.** Subject rows are keyboard-focusable, browser controls retain their native keys, bad stored JSON/tab choices fall back safely, help scrolls, narrow windows retain a view picker, tabs wrap, and sliders fit. Batch operations retain a visible label and Cancel/Escape.
- **Keyboard controls could bypass the batch lock.** Focused selects/ranges/checkboxes could still change the camera or stage through native events. Global keys and direct input/change handlers now enforce the same lock and restore readbacks. Notes and search remain editable, and cancellation remains available.
- **Failed startup leaked resources or left a stale fatal screen.** Engine.open now closes only its owned partial browser/server resources on failure. A validated inspector boot retry removes only its marked failure UI and clears the earlier error. Healthy inspector UI is preserved.
- **Camera inputs could allocate huge viewports or silently convert invalid numbers to null.** CLI and HTTP paths now validate viewport dimensions/pixel budget and finite framing/camera/move numbers before serialization or allocation. Failed jobs exit nonzero. Invalid zero sheet dimensions reach strict validation instead of silently selecting defaults.

## Agent and maintenance contract

`DWInspect.apiVersion === 1` exposes discovery, selection, camera, stepping, marine moves/kit/holds, model switches, zombie reactions, captures, batch checks, notes, errors, cancellation and session restoration. Agents use this API, not `_ix`. Recipes are `dw-inspector-session` schema 1; camera sidecars are `dw-camera-shot` schema 2 with an optional `inspect` recipe. Saved moves restart: this is setup reproduction, not a simulation checkpoint. Stable model switches and turntable yaw are included; recipes cannot invoke action buttons.

The crew's camera serializes shell and file-inbox jobs. Use a unique complete JSON file and read its matching result, an explicit target or recipe, and the actual PNG. Treat `{ok:false}`, a nonzero CLI status or a failed catalog case as a failure. An output file existing is not proof of the correct model. Session/log files are checkout-specific; idle pages freeze. A fresh audited inspector camera was left running for agent use.

New catalog entries adapt real builders and declare stable ID, variants, owner and source. New move recipes describe input and use cancellable game-clock waits. Do not copy joint rotations into the inspector. Run focused checks, the relevant model variants and actual animation/scene review after changing a builder or recipe. Claude was asked to register the additive public contracts centrally; that lead review is pending.

## Limits and remaining review

This is a curated 116-subject catalog, not every object or scene in the game. World places, valley-only actions, ladders, burial/parachute workflows, environmental contacts and door/window build modifiers still require actual game-scene review. Use the camera's title/match modes for those scenes. Live zombies and damage buttons test reactions; they do not prove projectile scoring or combat correctness.

Resource stability was measured over targeted rebuild cycles, not a multi-hour soak of every opaque builder. Rewind does not restore all simulation state, and recipes do not reproduce elapsed random effects. Cold desktop title budgets were not measured by the inspector tests; concurrent native load samples are not controlled cold-start benchmarks. The Windows server helper was exercised natively; the BAT's missing-Node prompt and default-browser fallback were inspected/tested by component rather than exercised in a broken installation.

Antigravity's independent AG-76 visual pass and Claude/Cursor's integration review remain requested. The full broader suite's unrelated failures need their owners; no gameplay assertions were removed or weakened to hide them.
