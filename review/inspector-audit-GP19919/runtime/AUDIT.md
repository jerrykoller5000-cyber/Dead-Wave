# GP-19919 runtime and agent API audit

The active inspector is `index.html?inspect` and `studio/inspector/`, launched by `Open Marine Inspector.bat`. This audit did not modify the old copied-model inspector in `tools/marine-inspector.*`, game combat rules, assets, seeds, or Git.

## Findings addressed in this task

1. **High: cancelled move sequences kept changing the next review.** Marine moves awaited game time without cancelling their continuations. Grenade charge bypassed the desk's tracked held keys; changing a move could leave G charged and later throw a grenade, while cancelled dive/fire/vault sequences could press keys, fire or build props after a new subject was selected. Reported to the UI/marine sub-audit and root; their `marine.js`/wait-queue cancellation fix owns this part. Stopping also releases debug holds, which previously persisted into subsequent moves.
2. **High: model switching leaked owned GPU resources.** `modelSubject.dispose()` and zombie statue respawn only detached objects. New buffers/materials/CanvasTextures survived repeated model checks. `subjects.js` now snapshots game-owned resources and releases only resources introduced by a subject that no remaining game/subject root uses. It also respects the existing explicit `userData.shared` convention, the weapon context, detached TT weapon/kit roots, and newly concurrent borrowers. Live zombies remain in the game's pool. Stage teardown releases overlays/materials and the grid even when that grid is hidden.
3. **High: stale asynchronous builders could move the marine off stage.** A delayed imported prop finishing after a newer marine selection added itself and called `placePlayer` before the selection token was checked. `modelSubject(..., {isCurrent})` now releases superseded results before any placement or scene attachment. Root supplies both the selection token and cancellation signal. Controls/measurement failures also release the partially constructed subject.
4. **High: agent batches had no stage lock or cancellation.** Concurrent show/check/screenshot operations could capture the wrong subject; frame waits could hang indefinitely. The supported API now exposes `apiVersion`, `capabilities`, `busy`, `cancel`, `session` and `restore`. Stage-changing jobs are exclusive and reject conflicting mutations; getters remain readable. Root bounds/cancels frame waits, and the API threads those signals through captures and selection.
5. **High: checks gave incomplete and misleading coverage.** Original checks built one variant of each ID and ran live zombie AI. They now check every catalog variant by default and use zombie statue geometry, report runtime journal errors, reject unmatched filters, retain any variant failure in the UI, and restore the previous subject/variant/mode/kit/holds/move/clock/camera even after cancellation. They remain geometry/runtime smoke checks, not gameplay or visual correctness assertions.
6. **Medium: turnaround sheets mixed poses and left the camera changed on failure.** Sheets now pause the pose for all views and restore camera/follow/play state in `finally`. View count, tile/column/pitch, image decoding, and canvas dimensions/pixels are bounded. Large collections require a smaller tile or narrower filter instead of trying to allocate an unlimited canvas.
7. **Medium: rewind reallocated and erased its history on reparenting.** The original recorder compared traversal order. Drawing/holstering the same nodes changed that order and reset all history. Stable indices now survive unchanged node membership; parent restoration removes changed edges first to avoid temporary cycles. Truly adding/removing rig nodes still resets history. The ring respects the actual configured memory and frame budget rather than forcing a minimum of 30 frames.
8. **Medium: Drive did not release the inspector camera.** Every inspector frame reasserted a shot camera after `release()`. Orbit now returns while driving. A selected view also resumes following after an external camera tool had disabled follow. Immediate camera setters return the accepted view instead of stale orbit state.
9. **Medium: axes used local positions as world positions.** Prop roots are children of their stage holder, so their axes appeared far away. Position and rotation now use the root's world transform.
10. **Medium: bounds and stats could misrepresent the model.** Instanced bounds ignored per-instance matrices; cached geometry bounds ignored changed vertex buffers; hidden or invalid geometry could reappear through the fallback. Bounds now include instance transforms, refresh on vertex-buffer version changes, and reject non-finite coordinates. Lines and points no longer count as triangles; the legacy drawn-object count is retained with an explicit `drawables` alias and point/segment fields.
11. **Medium: malformed numbers could poison camera, clock and rewind.** NaN/infinite camera coordinates, speeds, steps, rewind frames and budgets are rejected. Speed matches the documented 0.05–2x range. Prototype-inherited names (`constructor`/`toString`) no longer pass preset or overlay membership checks.
12. **Medium: imported review recipes could partially mutate before rejection.** The versioned session schema validates IDs, variants, modes, wardrobe choices, gun mods, booleans, holds, display settings and camera before mutating. Failed/cancelled recipe application restores the previous recipe. A recipe reconstructs a review setup and restarts its move; it is not a simulation save-state.
13. **Medium: named head reaction probes never confirmed a head hit.** The game now requires `headHit` (plus face/head metadata for military/brute), so changing hitY alone did not test a head reaction. The API uses the posed canonical `headRoot` height and the real classifier metadata. Body/leg heights scale with hitH. These are reaction probes, not ballistic traces.
14. **Medium: notes could falsely report success.** Notes now include a reproducible recipe, have finite capture/fetch waits, reject failed HTTP/endpoint responses, and share the screenshot job lock. Root/tooling owns server validation and persistence.
15. **High for motion review: Frame and bookmarks assumed an upright marine.** The previous fixed box and offsets could cut off a prone/dive/vault rig or aim a head/hands camera at empty space. Marine focus now uses cached visible rig bounds (at most 10 Hz except an explicit Frame/view refresh), with cheap world joints following each animation frame. Full/three-quarter retain their angles/minimum distances and fit the actual pose once; anatomical bookmarks use named joint world positions, and the hands view can widen once for separated grips. The camera does not change zoom every breathing frame. Optional `session.view` stores the follow bookmark/offset; old schema-one recipes remain valid, and turnaround sheets restore the anatomical follow state.
16. **Medium: standalone model switches were absent from review recipes.** Saved/restored suppressed weapons or opened/cutaway relay vaults reverted to the default model. All eight current switches now have stable IDs; `model.controls()/model.set()` expose validated toggle/select controls, while recipes never invoke buttons. Optional `session.model` records switch values, turntable speed and normalized yaw; the yaw setter also restores internal spin so the next tick cannot overwrite it. Unsupported switches fail with rollback. Model checks suppress unused rewind allocation and restore that flag before reconstructing the previous review.
17. **High: correct API/DOM state did not guarantee a fresh screenshot.** Root's native inbox images exposed a previous large M4 still presented while labels, triangles and API state already described the marine. A direct canvas capture explicitly redrew and corrected both canvas and later CDP images, pointing to stale GPU presentation rather than a retained subject. A fresh draw and GPU fence corrected clean canvas captures but did not reliably correct page captures with visible panels. `still(true)` now draws the held scene explicitly, awaits the public renderer GPU fence with a 15-second wall limit, then publishes a bounded 2D copy of the real renderer canvas beneath the panels. A one-pixel readback completes that buffer copy before external screenshots; no PNG is encoded or game time changed by the copy. Resume, any API operation that resumes the loop, cleanup, failure and cancellation remove the temporary canvas and zero its backing memory. Failed draws/fences/readbacks reject and resume rendering. Root owns fresh renderer-frame bookkeeping, inspector-aware camera UI masking, and the final real-image comparison; CPU control-flow tests cannot prove compositor output visually.
18. **High: pose bounds CPU-skinned an invisible duplicate of the marine.** Final native performance exposed a real regression after adding actual-pose bounds. The graph contains a visible=true `marine-shadow` SkinnedMesh with 237,474 vertices, whose custom layers reject the main camera. Measurements ignored layers and repeatedly skinned that shadow proxy despite the actual visible rigid body already being measured. In a serialized native GPU comparison, shadow skinning alone cost 23.51 ms per measurement. Bounds and subject statistics now honor the inspection camera's layers. Actual pose corners, visible skinned bones, instance transforms and changed cloth vertices remain measured. Corrected native bounds cost 0.485 ms mean / 0.7 ms p95 / 1 ms max, and the same live Marine improved from 52.51 to 58.92 FPS. Visible statistics also exclude the proxy's duplicate triangles (81,138 visible versus 160,332 graph triangles in this setup).

## Explicit limits / follow-up guidance

- Rewind stores rig transforms/visibility/parents, not arbitrary simulation state, morph/material uniforms, detached effects, or external deformation buffers. The marine flexible shirt is a useful exception: its `onBeforeRender` rebuilds the cloth from restored pelvis/chest transforms, so it is correctly reconstructed without copying its vertex buffers. Returning to play restores the newest pose.
- Review recipes reconstruct selection, kit, model switches, yaw, camera and holds; they do not capture the elapsed tick phase of shader/animal animations. A paused turntable angle does restore; arbitrary animated effects are not a simulation checkpoint.
- Every intentionally cached/shared geometry or material must use `userData.shared = true`. A shared material's maps are protected as well. An opaque builder closure's unmarked latent resource cache cannot be inferred from the scene. Existing marine-body, weapon-heavy, cargo-plane and PGB shared resources already use this convention.
- New draw-only subjects must not add unrelated objects to the live scene or persist state in their builder. `build` should return its owned root, use canonical game builders, and throw clearly on failure. Long-running custom builders must cooperate with the root cancellation gate.
- The current 16 build kinds mirror the canonical tiered-builder list, but the catalog is curated. Door/window/gate modifiers are not independently catalogued; M240 is already under weapons. Root was informed that auto-discovery claims must be narrowed or canonical build data/opening wrappers exposed.
- `makeCatalog` originally silently renamed duplicate IDs. Root was informed this should be an explicit stable-ID error; a final duplicate guard alone is ineffective after automatic renaming.
- Native rendering, performance/resource counters and real input parity were delegated to root's coordinated browser session. The CPU tests below cannot establish visual quality, GPU stability, or frame rate.
